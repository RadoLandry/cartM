# Research: Discipline & Category Taxonomy`n`n## Technical Context Clarifications`n`n### Taxonomy Source`n- **Decision**: Define a baseline "Canonical Taxonomy" seed in code (or DB) for combat sports/fitness, but allow the LLM to map existing unstructured tags/metadata into these buckets (`Boxe` -> `Boxing`, `Gant` -> `Gloves/Protection`).`n- **Rationale**: Ensures the `Data Model` enforces structured data integrity. LLM operates as a fuzzy matching engine against a known schema, reducing hallucinated disciplines.`n`n### Confidence Scores`n- **Decision**: Store a float `[0.0 - 1.0]` per classification. Flags `< 0.8` for manual review in the UI.`n- **Rationale**: 0.8 is standard for high-precision text classification. Allows merchants to focus their manual QA on edge cases rather than reviewing thousands of obvious matches.`n`n### Manual Override Flow`n- **Decision**: Overrides write exclusively to the PostgreSQL database, locking the entity from future re-classification upon sync.`n- **Rationale**: Real-time fine-tuning of an LLM per-merchant is too slow and costly for Shopify Edge/Serverless constraints. Overriding the DB guarantees 100% precision on fixed items.`n`n## Integrations`n- **LLM Provider**: Use Vercel AI SDK `generateObject` with Zod schema (`z.object({ discipline: ..., category: ..., confidence: ... })`) to ensure structured outputs.`n- **Shopify Setup**: `Admin API` fetches the unclassified product batches during onboarding.`n- **UI Layer**: Polaris `IndexTable` or `ResourceList` for the review UI.
