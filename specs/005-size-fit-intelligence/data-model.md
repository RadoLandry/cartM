# Data Model: Size & Fit Intelligence

## New Prisma Models

### SizeChart

Stores the breakpoint mapping from body attributes to size labels for a product category. One row per `(shop, categoryTag, sizeSystem)` combination.

```
SizeChart
├── id               String    @id @default(cuid())
├── shop             String
├── categoryTag      String    -- matches Product.categoryTags values (e.g., "gloves", "shorts", "rashguard")
├── sizeSystem       String    -- "clothing" | "gloves_oz" | "waist_inches" | "weight_class"
├── breakpoints      Json      -- auto-generated; array of SizeBreakpoint objects (see schema below)
├── overrideBreakpoints Json?  -- merchant-set; when present, takes precedence over breakpoints
├── source           SizeChartSource @default(AUTO)
├── version          Int       @default(1)
├── createdAt        DateTime  @default(now())
└── updatedAt        DateTime  @updatedAt

@@unique([shop, categoryTag, sizeSystem])
@@index([shop])
```

**SizeBreakpoint JSON schema** (element of `breakpoints` / `overrideBreakpoints` array):
```json
{
  "label": "M",
  "attributeType": "chest_cm" | "waist_cm" | "weight_kg" | "weight_class" | "oz",
  "min": 88,
  "max": 96,
  "note": "optional merchant note shown alongside recommendation"
}
```

### CrossSizeMapping

Encodes the expected size correspondence between two product categories. Used for conflict detection.

```
CrossSizeMapping
├── id                  String   @id @default(cuid())
├── shop                String
├── sourceCategoryTag   String   -- e.g., "shorts"
├── sourceSize          String   -- e.g., "M"
├── targetCategoryTag   String   -- e.g., "rashguard"
├── targetSize          String   -- e.g., "M"
├── severityOnMismatch  SizeConflictSeverity @default(WARNING)
├── source              SizeChartSource @default(AUTO)
├── createdAt           DateTime @default(now())
└── updatedAt           DateTime @updatedAt

@@unique([shop, sourceCategoryTag, sourceSize, targetCategoryTag])
@@index([shop, sourceCategoryTag])
@@index([shop, targetCategoryTag])
```

---

### SizeReturnRecord

Stores individual return events with size and reason data. Feeds the statistical size chart adjustment job.

```
SizeReturnRecord
├── id                String   @id @default(cuid())
├── shop              String
├── shopifyOrderId    String
├── shopifyProductId  String
├── categoryTag       String
├── returnedSize      String
├── returnReason      String   -- "too_small" | "too_large" | "other"
├── returnedAt        DateTime
├── processedForAdjustment Boolean @default(false)
├── createdAt         DateTime @default(now())

@@index([shop, categoryTag])
@@index([shop, processedForAdjustment])
```

## New Enums

```
enum SizeChartSource {
  AUTO       // generated by catalog sync or LLM analysis
  MERCHANT   // set by merchant via admin UI
}

enum SizeConflictSeverity {
  WARNING  // unusual combination but physically possible
  ERROR    // definitively incompatible (e.g., child product + adult product)
}
```

## Existing Model Extensions

### ProductVariant (existing)

The `sizeCategory` field already exists but is currently a free-text string. This feature introduces a controlled vocabulary for its values to match `SizeChart.categoryTag`:

| sizeCategory value | Meaning |
|---|---|
| `gloves_oz` | Boxing / MMA gloves measured in ounces |
| `shorts_waist` | Shorts or board shorts measured by waist |
| `clothing` | Generic S/M/L/XL apparel (rashguards, tops, compression) |
| `headgear` | Headgear with S/M/L sizing |
| `shinguard` | Shin guards with S/M/L sizing |
| `weight_class` | Items whose fit depends on athlete weight class |
| `one_size` | Products with no meaningful size variation |

The `sizeNumeric` field stores the numeric interpretation of `sizeValue` (e.g., 16 for "16oz", 32 for waist "32\"").

No migration is required to add new columns; `sizeCategory` and `sizeNumeric` already exist in the schema.

## Relationships Between Models

```
SizeChart      1──── linked by categoryTag ────N  ProductVariant.sizeCategory
CrossSizeMapping  ────links two categoryTags────   (no FK, resolved by tag matching)
SizeReturnRecord ──── linked by shopifyProductId ─── Product.shopifyProductId
```

Cross-size mappings and size charts are resolved at query time by matching the `categoryTag` string — not by foreign key — so the models remain decoupled from the product catalog sync lifecycle.

## Query Patterns

### Size recommendation lookup
```
SELECT * FROM SizeChart
WHERE shop = $shop
  AND categoryTag = $categoryTag
  AND sizeSystem = $sizeSystem
LIMIT 1
-- then apply overrideBreakpoints if present, else breakpoints
-- binary search the array for the customer's attribute value
```

### Conflict detection for a cart
```
SELECT * FROM CrossSizeMapping
WHERE shop = $shop
  AND (
    (sourceCategoryTag = $catA AND targetCategoryTag = $catB) OR
    (sourceCategoryTag = $catB AND targetCategoryTag = $catA)
  )
-- compare resolved mapping against actual cart item sizes
-- emit conflict record if mismatch
```

### Return-data adjustment eligibility
```
SELECT categoryTag, returnedSize, returnReason, COUNT(*) as count
FROM SizeReturnRecord
WHERE shop = $shop
  AND processedForAdjustment = false
GROUP BY categoryTag, returnedSize, returnReason
HAVING COUNT(*) >= $MIN_RETURN_SAMPLES
```
